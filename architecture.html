CredScope AI: Proposed Architecture Solution

A comprehensive overview of the AI-enabled Financial Health Report system. This document outlines the proposed end-to-end implementation built for the MSME Financial Health Card Assignment, followed by a strategic alternative design demonstrating integration with India's Digital Public Infrastructure.

Important Note on Scope: In this implementation, active Machine Learning (XGBoost) models have been custom-built specifically for three core targets: 1) Overall Financial Health Score, 2) Credit Eligibility, and 3) Recommended Credit Limit. The remaining sub-scores (Business Stability, Cash Flow, Revenue Consistency, Payment Behaviour, Business Growth, and Compliance) are currently represented as static UI placeholders to fulfill UI requirements, and will be integrated with dedicated ML models in future iterations.

1 End-to-End System Architecture (Current Implementation)

Technology Stack

  • Frontend: Next.js (React), Tailwind CSS, Glassmorphism UI
  • Backend API: FastAPI (Python), Uvicorn, Pydantic (Schema Validation)
  • ML Pipeline: XGBoost (Regression & Classification), Scikit-Learn
  • Explainability: SHAP (TreeExplainer) for neural interpretability

Data Ingestion & ML Workflow

Raw alternative data (GST, UPI, Banking) is passed to the FastAPI endpoint. The backend strictly shares the feature engineering module (utils.py) with the offline ML pipeline to prevent data drift. The data is transformed via a Scikit-Learn ColumnTransformer and fed into three parallel XGBoost models to predict the Health Score, Credit Eligibility, and Credit Limit.

What is Currently Integrated in Code

Implemented: The Next.js frontend, FastAPI backend, feature engineering pipeline, and the three XGBoost models alongside SHAP explainers are fully operational and integrated in the current codebase.

Not Implemented (Simulated): The LLM/GenAI layer for textual risk insights and the DPI/Account Aggregator live APIs are currently simulated/mocked for demonstration purposes.

2 Integration Strategy (India DPI Alternative Design)

To achieve true financial inclusion and straight-through processing (STP) for MSMEs, the system must shift from manual data entry to a fully integrated digital ecosystem. The architecture below demonstrates how CredScope AI acts as a Credit Underwriting Engine sitting between India's consent-based Digital Public Infrastructure (DPI) and modern lending networks (OCEN/ULI).

Account Aggregators & Banking

Instead of manual CSV uploads, the system will act as a Financial Information User (FIU). It will parse raw JSON bank statements and UPI transaction hashes provided by AAs to compute features like Cashflow_Stability_Index in real-time.

GSTN Integration

GSTN APIs will provide cryptographically verified GSTR-1 and GSTR-3B filings. This data feeds directly into our GST_Filing_Timeliness_Pct and Monthly_GST_Sales_INR metrics, ensuring the ML model operates on fraud-proof alternative data.

ULI & OCEN Networks

Once the Financial Health Score and SHAP insights are generated, they are formatted as a standardized JSON response and pushed to the Open Credit Enablement Network (OCEN) or Unified Lending Interface (ULI). This allows multiple lenders to consume our ML-derived risk metrics instantly.
